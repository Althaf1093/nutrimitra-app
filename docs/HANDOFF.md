1. What the product is
NutriMitra is an AI wellness companion for India, English and Telugu. A user onboards (body, diet, allergies, goal), gets an adaptive 7-day Indian-focused meal plan, logs meals (manually or by photo), logs activity and weight, chats with an AI coach, gets reminders, and can sync steps/sleep from HealthKit or Health Connect. It was generated by Emergent.sh's AI builder (Sep 11-15, 2026) and is now maintained locally.

3. Architecture
Phone / web (Expo + React Native)
   |  HTTPS + Bearer token (JWT)
FastAPI  (backend/server.py, all routes under /api)
   |-- MongoDB (11 collections)
   |-- Groq API  (coach, plan generation, photo recognition if a vision model exists)
   |-- Emergent services  (Google login start page + verification endpoint; optional LLM key)
Everything else (reminders, health reads) runs on the phone itself.

4. Backend (backend/server.py)
Config (C): env vars MONGO_URL (required), JWT_SECRET (required, no fallback), DB_NAME (default nutrimitra), GROQ_API_KEY, GROQ_MODEL (default openai/gpt-oss-120b), GOOGLE_AUTH_HANDOFF_URL, EMERGENT_LLM_KEY. A template is in backend/.env.example.

Auth (C): email + password (bcrypt), JWT HS256 valid 72 hours. current_user first tries the JWT, then falls back to a 7-day session token from the user_sessions collection (used by Google login). Passwords must be 8-128 characters.

24 routes (C):

Method and path	Auth	What it does
GET /api/	no	Status and AI model name
POST /auth/signup, /auth/login	no	Email accounts; 409 if email exists, 401 if wrong
POST /auth/session	no	Exchanges an Emergent-managed Google session_id for a user and 7-day token
GET /me, PUT /profile	yes	User + profile; upsert profile and mark onboarding complete
GET /plan	yes	Latest plan if under 7 days old, otherwise regenerates; 409 if no profile
POST /plan/regenerate	yes	Force a new plan (Groq, validated, with fallback)
GET /dashboard	yes	Today's meals/activities, calories, a "readiness" number
POST /meals, /activities, /weight	yes	Insert log entries (no edit or delete exists)
GET /progress	yes	Up to 100 weights and activities, plus a fixed review sentence
GET /coach/history, POST /coach	yes	Chat with memory (last 12 messages), recipe-card parsing
GET /ingredients	no	Search a hard-coded list of 10 ingredients
GET/POST /permissions	yes	Flags: health_sync, wearables, analytics, coach_memory
POST /coach/vision	yes	Photo to nutrition estimate (user confirms)
GET /eat-now	yes	Calorie target and next suggested meal
GET/PUT /reminders	yes	Reminder preferences (stored; scheduling happens on the phone)
POST /health/sync, GET /health/summary	yes	Privacy-gated ingestion and today's device totals
MongoDB collections (C): users, profiles, plans, meals, activities, weights, coach_messages, permissions, reminders, health_records, user_sessions. No indexes are created anywhere.

Key flows (C):

Plan generation: builds context (profile, last week's logged meals, activity count, recent weights), asks Groq for strict JSON (7 days x 4 meals), then coerce_plan validates shape and clamps numbers. plan_restriction_violations (added by us) rejects plans that contain meat/egg for vegetarians, dairy/honey for vegans, or any listed allergy/dislike. On any failure the deterministic local_plan fallback is used.
Coach: system prompt + profile JSON + last 12 stored messages. The model may append a fenced recipe JSON block, which is parsed, clamped, shown as a card, and loggable as a meal. If Groq fails, a canned reply is returned.
Photo recognition: pick_vision_model queries Groq's model list for a vision-capable model each call. If none, it tries emergent_vision (needs EMERGENT_LLM_KEY and Emergent's private package). If both fail, HTTP 502.
Eat now: Mifflin-St Jeor calorie target x activity factor +/- goal adjustment, floored at 1,200, minus today's logged calories.
Health: records are accepted only if the user enabled health_sync (403 otherwise), max 1,000 per batch, upserted by (external_id, source).

Structure (C):

State: AuthContext (src/context/auth.tsx) holds session status (loading | anon | onboarding | ready), user, profile and language. Each screen fetches with api() and useState. React Query is installed and wrapped around the app, but no screen uses it.
API client: src/api.ts adds the Bearer token; the backend URL comes from EXPO_PUBLIC_BACKEND_URL baked in at build time.
Token storage: SecureStore on phones; localStorage on web.
i18n: src/i18n.ts, 111 keys each for English and Telugu, plus a bundled Noto Sans Telugu font for web. Many strings are still hard-coded in English.
Shared components: ui.tsx (AppIcon, Button, Chip, Field, MealCard), readiness-card.tsx, device-activity-card.tsx, vision-confirm-form.tsx, error-boundary.tsx.
Reminders: src/lib/notifications.ts schedules local notifications on the phone (meals 08:00/13:00/19:30, water every 3 h, movement every 2 h, weekly Sunday 18:00). No server push exists.
Health: src/lib/health/ lazily loads HealthKit (iOS) or Health Connect (Android). It only works in a real build, not Expo Go. It reads the last 24 hours (steps, distance, active calories, workouts, sleep) and posts to /health/sync.
Google login: the app opens https://auth.emergentagent.com/?redirect=... (overridable with EXPO_PUBLIC_GOOGLE_AUTH_URL), receives a session_id, and the backend verifies it with an Emergent endpoint (auth.tsx line 32, server.py lines 167-170).
App config (app.json, C): name and slug frontend, scheme frontend, bundle/package ID com.emergent.healthcoachindia.g49zwk. Permissions: camera, notifications, health reads. Plugins: expo-router, splash, font, notifications, image-picker, HealthKit, Health Connect. There is no eas.json.

7. Findings (what is wrong or missing)
Store blockers
Emergent branding ships in the app (V). icon.png is the Emergent "e" logo on a blue grid. splash-image.png is a black screen reading "Start building apps on emergent". I did not open adaptive-icon.png or favicon.png; assume they need replacing too. The file names partial-react-logo.png and react-logo*.png suggest Expo template leftovers (I)).
Wrong identity (C). Display name frontend; bundle ID contains "emergent" and a random suffix. Store IDs are permanent, so choose the final name and ID before the first submission.
Photo recognition does not work (V). This Groq key lists no vision model and there is no Emergent key. It is the headline feature.
Google login depends on Emergent at both ends (C). The start page and the verification endpoint are Emergent's. It must be rebuilt with your own Google credentials (free) to leave Emergent.
Legal and account basics are missing (C). No privacy policy, terms, consent checkbox, in-app account deletion, password reset, or email verification.
Health data goes to a third party (C). The full profile (including conditions and allergies) is sent to Groq on every coach and plan call. Store data-safety forms and the privacy policy must say so.
Apple login rule (corrected). Apple's guideline 4.8 requires an equivalent privacy-focused login option alongside third-party logins like Google. Sign in with Apple guarantees compliance but is not strictly mandated. My earlier statements that it is "required" were too strong. Confirm against Apple's current text before submitting. Source: Apple App Review Guidelines.
Real bugs
The Today screen always shows Day 1 of the plan (V). todayPlan = plan?.days?.[0] (index.tsx line 90) and eat_now uses [:1], so the 7-day plan never advances by weekday.
Google-created accounts crash email login (V at library level). Their password_hash is "", and bcrypt.checkpw raises ValueError: Invalid salt, which is an unhandled HTTP 500.
"Today" uses UTC dates (C). For India the day rolls over at 05:30 IST, so a 1 a.m. snack counts toward yesterday.
Logs cannot be corrected (V and C). No DELETE or PATCH routes exist (C). On the live Today screen the "+" button stayed after meals were logged, so a plan meal can be logged repeatedly (V). No server code ever sets a plan meal's logged flag (C).
Fallback meals all show 430 kcal / 24 g protein (V). portion_for() hard-codes them, so users see identical numbers whenever the AI is not used (rate limit, outage, restriction violation).
Groq rate limits fail silently (V). HTTP 429 leads to generic replies or the fallback plan with no message to the user.
Typo in the plan prompt (C). "fat_g: number} is missing a quote (server.py line 274).
Scale, safety and quality
No MongoDB indexes (C). Email uniqueness is a find-then-insert (race condition); queries by user_id are unindexed; expired user_sessions are never cleaned up.
No rate limiting or brute-force protection on login (C). CORS allows all origins.
Health conditions are collected but not enforced (C). Plans respect diet, allergies and dislikes only. The minimum age is 13 with weight-loss goals available, which deserves a deliberate decision.
Made-up "readiness" score (C). min(96, 64 + 7 x activities + 4 x meals); it is not based on health data. Walk/strength buttons log fixed estimates (120/80 kcal) regardless of duration.
HealthKit step double-counting risk (I). Steps from all sources are summed; iPhone plus Apple Watch may double count. Verify on a device.
Mixed-language UI (C). Many strings are hard-coded English (settings labels, coach quick prompts, "Day N", "Back", etc.).
Settings toggles with no effect behind them (C). "Supported wearables" and "Anonymous product analytics" only store a flag.
Housekeeping
LogBox.ignoreAllLogs(true) hides all warnings. React Query unused. Likely unused packages: date-fns, dayjs, expo-blur, expo-haptics, expo-linear-gradient, react-native-dotenv, react-native-webview (others in the "no direct import" list are required peers; check before removing).
requirements.txt includes heavy packages the server never imports (pandas, numpy, boto3, passlib, python-jose, typer, jq, dev tools); deprecated @app.on_event; db.plans grows on every regeneration.
Emergent leftovers likely removable once you leave (confirm first): .emergent/, frontend/scripts/cmd-guard* (a preinstall guard that blocks deprecated packages such as expo-barcode-scanner; use expo-camera for barcodes), test_reports/, test_result.md, image_testing.md.
Unverified on any real device: Google OAuth, HealthKit, Health Connect, notifications, camera.

10. How to run it (Windows)
Docker Desktop running. If it will not start, delete its stale socket files through WSL. Check readiness with docker version --format '{{.Server.Version}}', not docker info.
docker start nutrimitra-mongo
Backend: cd backend, then .venv\Scripts\python.exe -m uvicorn server:app --host 0.0.0.0 --port 8001
Frontend: cd frontend, then CI=1 npx expo start --web. CI=1 is required.
If the app hangs on a spinner, the PC's LAN IP changed. Update EXPO_PUBLIC_BACKEND_URL in frontend/.env and restart Expo.
Tests: set EXPO_PUBLIC_BACKEND_URL=http://localhost:8001, then .venv\Scripts\python.exe -m pytest tests/ -n 0 --ignore=tests/make_test_image.py. Do not run the suite repeatedly back to back (Groq rate limit).
